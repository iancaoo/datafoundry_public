# DTC 增长分析演示案例

这个案例用于演示 DataAgent 如何帮助业务用户在自然语言里完成一次经营复盘：先理解数据结构，再执行只读查询，最后把 SQL、表格、结论和追溯过程沉淀下来。

## 适合展示给谁

- 电商运营、增长负责人、品牌方老板。
- 想评估自然语言数据分析、SQL 审计和分析产出能力的团队。
- 想看 DataAgent 是否能支撑真实业务追问，而不是只做简单指标查询的用户。

## 业务背景

某美妆 DTC 品牌在 2026-06-24 至 2026-06-30 的 GMV 明显上涨，但财务发现毛利率下降，客服投诉也变多。运营负责人希望快速判断：

- 增长主要来自哪个渠道？
- GMV 增长是否健康？
- 利润没有同步增长的原因是什么？
- 下周预算应该怎么调整？

## 准备数据

在仓库根目录运行：

```bash
npm run seed:dtc-growth-demo
```

脚本会生成 SQLite 数据库：

```text
storage/fixtures/dtc-growth-demo.sqlite
```

如果本地 API 已启动，脚本会自动注册数据源：

```text
dtc-growth-demo
```

如果 API 没有启动，可以先运行：

```bash
npm run dev:api
npm run seed:dtc-growth-demo
```

或者在 Web 工作台的数据源面板中手动添加：

- 类型：`sqlite`
- 名称：`DTC Growth Demo`
- 文件路径：`storage/fixtures/dtc-growth-demo.sqlite`

## 数据表

数据库包含 5 张表：

| 表名 | 用途 |
| --- | --- |
| `orders` | 订单、GMV、折扣、成本、退款、新客标记。 |
| `ad_spend` | 渠道投放、活动、曝光、点击和花费。 |
| `products` | 商品、品类、标价、单位成本和供应商。 |
| `customer_tickets` | 客服工单、问题类型、情绪和处理时长。 |
| `daily_targets` | 每日 GMV、毛利率和退款率目标。 |

## 推荐提问顺序

第一问先让 Agent 看 schema，展示「先理解结构再查询」：

```text
请先查看 dtc-growth-demo 数据源里有哪些表，并说明每张表适合回答什么业务问题。
```

第二问进入经营复盘：

```text
对比 2026-06-24 到 2026-06-30 和 2026-06-17 到 2026-06-23，GMV、订单数、客单价、净毛利率、退款率分别有什么变化？请指出最值得关注的异常。
```

第三问展示跨表分析：

```text
把最近 7 天的 GMV 增长按渠道拆开，并结合 ad_spend 计算每个渠道的投放 ROI。哪个渠道带来了增长，但质量可能不好？
```

第四问展示诊断能力：

```text
为什么 GMV 增长了，但利润没有同步增长？请从折扣、商品结构、渠道投放和退款四个角度分析，并给出证据。
```

第五问展示可行动建议：

```text
如果下周预算只能增加 20%，请给出渠道预算调整建议，并说明依据。请生成一份适合运营周会的结论摘要。
```

## 预期看点

演示时可以重点观察这些结果：

- 最近 7 天 GMV 和订单数上涨，但净毛利率下降。
- 抖音渠道贡献了最多增量，但折扣和投放花费明显放大。
- 天猫存在退款订单，退款率会拖累整体利润。
- 小红书增长更稳，适合作为预算加码对象。
- 客服工单集中在优惠说明、物流和退款问题上，可以作为运营动作的补充证据。

## 演示话术

可以这样介绍：

> DataAgent 不是简单把自然语言翻译成 SQL。它会先检查数据源 schema，再在只读边界内执行查询，并把每一步 SQL、结果表格和分析结论留在追溯面板里。业务同学可以直接问经营问题，数据同学也能复核每一步是否可信。

结尾可以引导用户关注：

- 业务问题是否能多轮追问。
- SQL 和结果是否可追溯。
- 表格、报告等产出是否能复用。
- 数据源凭据是否不会暴露给模型上下文。
